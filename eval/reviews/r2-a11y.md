# r2 accessibility review: directions a, b, c

Reviewer: accessibility specialist, fresh eyes. Date: 2026-10-17.
Scope: `proto/out/{a,b,c}/index.html`, their CSS, `proto/build.mjs`. The automated pass (html-validate, axe, 24px targets, focus-visible presence, overflow sweep) is clean; everything below is what it does not catch.

Method: Playwright + Chromium, served with `eval/serve.mjs`. Scripts were run from the scratch directory, not the project:
- full Chromium AX tree via CDP `Accessibility.getFullAXTree` (roles, names, landmarks)
- a keyboard Tab walk at 1280 and 375 px that records the focused element, its computed outline and, for SVG nodes, the rect stroke
- `emulateMedia({ forcedColors: 'active' })` in light and dark, with computed styles and screenshots
- `emulateMedia({ media: 'print' })` in light and dark, with computed colours
- the WCAG 1.4.12 text-spacing bookmarklet CSS at 1280 and 320 px, with SVG text bbox compared to its rect
- token contrast worked out from `tokens.css` with the WCAG relative-luminance formula

Tags: **fix** means do it before the direction ships. **note** means a judgement call, or fine as it is.

## Direction C: the question map

### C1. The map's relationships are invisible to screen readers, and the questions exist only in the map. **fix**
- Element: `figure.map-figure > svg.map[role=group]`, the `.edge` paths, and the `#aap / #authorship-strategy / #attention-not-self .work-name::before` squares.
- WCAG: 1.3.1 Info and Relationships, and 1.1.1 for the squares.
- Evidence: in the AX tree, `figure` (no name) → `group "How the two practices lead to three questions"` → 5 flat links. The edges (which practice asks which question, and that "Does the origin travel with the idea?" comes from *both*) are not exposed in any form. The question wording appears nowhere in the list below the map. The `::before` square that marks "this project carries a question" is a CSS shape with no text equivalent. Print hides `.map-figure` (`base.css` print block), so on paper the questions are lost for everyone.
- Fix: give each question-carrying project a visible line in its list item, e.g. `<p class="work-question">Asks: Who answers when an agent fails?</p>`, and drop the `::before` square or keep it as decoration next to that text. The list already encodes the edges through section membership (AAP is under agents, Attention Not Self is under mind, Authorship Strategy is under "Where the two meet"), so once the question is in the list, the list stands alone and the map becomes a visual summary of it. Then give the figure a `<figcaption>`, visible or `.visually-hidden`, e.g. "Map: each practice leads to the questions its projects ask; the same links are in the list below". Keep the `role=group` label short. Print then keeps the questions automatically.

### C2. The map duplicates the list's navigation and adds 5 tab stops with no heading. **note** (becomes fix if C1 is not done)
- Evidence: Tab walk (375 and 1280): after "Every article and essay, in one list" come 5 map links, then the list. The map has no heading, so in heading navigation it reads as part of the hidden "Read and follow" h2 section.
- Fix (choose one): (a) keep the map focusable, since it is a reasonable pointer and keyboard shortcut, and add the figcaption from C1. Optionally wrap it in `<nav aria-label="Question map">` so it is a named landmark rather than an anonymous group after the platform nav. Or (b) once C1 puts the questions in the list, make the figure `aria-hidden="true"` and its links `tabindex="-1"`, so the list is the single keyboard and screen-reader path and the map is pointer-only. (a) is less surprising for sighted keyboard users. Either way, don't leave the map unnamed between two sections.

### C3. In the narrow map, focus order jumps bottom → top. **fix**
- Element: `svg.map--narrow` node order (`nodes()` in `build.mjs` emits both practices first, then the questions).
- WCAG: 2.4.3 Focus Order (and 1.3.2 for reading order).
- Evidence: Tab walk at 375 px, focus y-positions: Building AI agents 421 → Watching the mind 813 → question 1 526 → question 2 617 → question 3 708. Focus goes to the bottom pill, then back up to the middle.
- Fix: for the narrow variant, emit nodes in visual order: agents, q1, q2, q3, mind. The wide variant's order (top row, then bottom row) is already fine.

### C4. Map edges, question-node outlines and the square markers are below 3:1. **fix**
- Element: `.edge`, `.node--question rect` stroke, the `::before` squares, all `--color-accent-line`.
- WCAG: 1.4.11 Non-text Contrast (the edges are the only carrier of "which practice asks which question").
- Evidence: `--color-accent-line` against the background is **2.60:1** in light (#bf975e / #fafbfb) and **2.60:1** in dark (#7f5a20 / #1d2128).
- Fix: raise `--color-accent-line` in `proto/tokens.mjs` for direction C to ≥3:1 in both schemes (B's line tokens already sit at 3.0). If C1 lands, the edges stop being the only carrier and this softens to a note, but it is cheap to fix.

### C5. The forced-colors focus rule for map nodes is dead, and the map ignores the user's high-contrast palette. **fix**
- Element: `base.css` `@media (forced-colors: active) { .node:focus-visible rect { stroke: Highlight } }`, overridden by `c/style.css` `.node:focus-visible rect { stroke: var(--color-text) }`, which loads later with equal specificity. Also `.node rect`, `.node text`, `.edge`.
- WCAG: 1.4.11 / 2.4.7 in forced-colors mode. Best practice for Windows High Contrast.
- Evidence: in forced colors (dark), a keyboard-focused question node computes `stroke: rgb(237,239,241)` (the token), not Highlight (`rgba(0,230,255,0.8)`). Chromium does not force SVG `fill`/`stroke`: the rects keep `fill:#1d2128` / `#fafbfb`, the text keeps the token colour, and the edges keep #7f5a20 / #bf975e. The map renders in the author palette rather than the user's theme, and the node links do not show as LinkText (screenshot `fc-dark-c-mapfocus.png`, scratch).
- Fix: move the forced-colors block into `c/style.css` after the normal rules, or raise its specificity:
  ```css
  @media (forced-colors: active) {
    .node rect { fill: Canvas; stroke: LinkText; }
    .node text { fill: LinkText; }
    .edge { stroke: CanvasText; }
    .node:focus-visible rect { stroke: Highlight; stroke-width: 4; }
  }
  ```

### C6. The practice-node focus indicator is only a stroke thickening. **fix**
- Element: `.node--practice:focus-visible` (`outline: none`; the rect stroke goes from 1.5 to 3 in the same `--color-text`).
- WCAG: 2.4.7 Focus Visible (passes, but weakly). 2.4.13 Focus Appearance (AAA) fails.
- Evidence: screenshot of the wide map with "Building AI agents" focused. The only change is a slightly bolder pill outline, and in the narrow map (scale 0.755) that is about 1.1 → 2.3 CSS px. Question nodes are fine: they change colour (accent-line → text) as well as width.
- Fix: Chromium draws `outline` on an SVG `<a>` around its bbox (tested). Drop `outline: none` and use the site ring, `.node:focus-visible { outline: 2px solid var(--color-text); outline-offset: 4px; }`, keeping the stroke change if wanted. That also matches every other focusable element on the page.

### C7. SVG text does not reflow under text spacing, and is small at 320 px. **note**
- WCAG: 1.4.12 Text Spacing, 1.4.4.
- Evidence: with the 1.4.12 overrides, "travel with the idea?" measures 265 units against a 250-unit rect (wide) and a 230-unit rect (narrow), so it runs over the box border. At 320 px viewport (400% zoom of 1280) the narrow SVG is 272 px wide, so 17-unit text renders at about 12.8 px. It still scales with page zoom, so this is not a 1.4.4 failure.
- Fix: widen question rects by about 10%, or shorten that line break ("Does the origin travel / with the idea?"). With C1 the same text is also in HTML, where it reflows.

## Direction B: two paths

### B1. Forced colors erase the meeting section's two-tone line and merge the two path colours. **fix**
- Element: `.meeting` background `linear-gradient(...)` lines; `.practice` / `.practice--mind` border colours.
- Evidence: forced colors (light and dark) compute `.meeting { background-image: none, none }`, so the "one line, both colours" that carries "where they meet" disappears. Both `.practice` borders and `.merge-right` become CanvasText, so the two paths are the same colour (screenshot `fc-dark-b.png`: two white lines, the corner join, then a meeting block with no line).
- Fix: draw the meeting line with borders, which survive forced colors, or add
  ```css
  @media (forced-colors: active) {
    .meeting { border-inline-start: calc(var(--line-path) * 3) double CanvasText; }
    .practice--mind, .merge-right { border-style: dashed; } /* optional: keep the two paths distinct */
  }
  ```

### B2. The two path colours differ only in hue. Same luminance, and the dark tokens sit just under 3:1. **note**
- WCAG: 1.4.1 Use of Color, 1.4.11.
- Evidence: agents-line and mind-line are 3.02 / 3.01:1 in light and **2.99 / 2.99:1** in dark, so their luminance is identical. In greyscale, or for achromatopsia, the lines and the two-tone meeting line look the same. Blue against amber does survive deuteranopia and protanopia. Every relationship the lines express is also in text: the section headings and "Where the two meet". Under 1.4.1 that makes the colour redundant, not the sole carrier, so this is a note.
- Fix (cheap): nudge both dark line tokens to ≥3.0. If you want the lines to read without hue, give one path a different texture (B1's dashed variant) everywhere, not only in forced colors.

## Direction A: the sentence, glossed

### A1. Quoted section titles put curly quotes into heading and landmark names. **note**
- Evidence: AX names are `heading "“Building AI agents”"` and `region "“Building AI agents”"`. NVDA (punctuation level "most"/"all") and some braille tables will voice or show the quote marks in the headings list and the landmarks list.
- Fix (optional): keep the visible quotes but generate them with `q::before/::after { content: open-quote / close-quote }`, as now, and set `aria-labelledby` on the section to a span inside the `q`. Alternatively accept it: the quotes are the design's commentary device, and they are not wrong.

### A2. The sentence links point to sections whose headings don't repeat the link text. **note**
- Evidence: "judgment, authorship, and human attention" → `#meet`, headed "Where the two meet". The link text is self-explanatory (2.4.4 passes), but a screen-reader user who follows it lands on a heading with different words.
- Fix: none required. Could add `aria-describedby` pointing to a short hint, but the gain is small.

## All directions

### X1. In dark-scheme print, muted text and A's accent titles print at about 3:1 or less. **fix**
- Element: `base.css` `@media print` sets `body { color: black; background: none }`, but elements with token colours keep their dark-scheme values.
- WCAG: 1.4.3 for printed output (best practice; WCAG does not strictly scope print).
- Evidence: `emulateMedia({ media: 'print', colorScheme: 'dark' })`: `.work-links a` / `.entrance-what` / `dt` compute #8e9792 / #9097a2 / #9198a7 on white paper (3.0 / 2.94 / 2.90:1). A's `.section-title` computes #6caa81 (2.73:1). Whether a browser prints in dark scheme varies, but the CSS should not depend on it.
- Fix: in `@media print`, force the light palette, e.g. `:root { color-scheme: light; }`, plus re-declare the light token values (or emit the light tokens inside `@media print` from `tokens.mjs`).

### X2. Print drops information. **fix** for C (covered by C1); **note** for the rest
- Evidence: C hides the map in print, so the questions disappear (see C1). In-page and footer links don't print their targets, which is right for `#…`. The "Every article and essay, in one list" link (`.entrance-index a`) is an external link whose URL does not print (`::after` content `none`).
- Fix: add `.entrance-index a[href^="http"]::after` to the print href rule.

### X3. The platform entrances use `dl` / `dt` / `dd`. **note**, acceptable
- Evidence: Chromium exposes DescriptionList → term / definition, and the `div` wrappers are valid. VoiceOver announces "description list". NVDA/JAWS announce it as a list counting dt and dd together (13 items) without grouping. In each `dd` the link and its `.entrance-what` span have no whitespace between them in the source, so with CSS off, in reader views and in copied text it reads "Dev.tobuild notes".
- Fix: insert a real separator, e.g. `${a(...)} <span class="entrance-what">…</span>` with a literal space (the flex column-gap already handles the visual spacing), or put the descriptor in parentheses for the unstyled case. The `dl` itself can stay.

### X4. The visually-hidden " for {project}" link suffixes. **note**, working as intended
- Evidence: link names read "Repository for harness-scope", "Zenodo (DOI) for Agent Attribution Practice", and so on. Every name starts with the visible label, so 2.5.3 Label in Name passes for voice control ("click Repository"). The hidden span sits at its static position next to the link (checked bbox), so VoiceOver's cursor box doesn't stretch.
- Fix: none.

### X5. `lang` attributes. **note**, pass
- Evidence: the only Japanese text is the nav link `<a lang="ja" hreflang="ja">日本語</a>`, which is correct. Platform names (Zenn, note) are Latin-script brand names and need no `lang`.

### X6. Landmarks and heading outline. **note**, fine
- Outline (all three): h1 name → h2 "Read and follow" (hidden) → h2 per practice → h3 per work → h2 "Where the two meet" → h3. No skipped levels. Each `section[aria-labelledby]` becomes a region landmark (4 in main, plus 2 navs). That is acceptable for a one-page site. Dropping `aria-labelledby` from the intro section would remove one redundant "Tatsuya Shimomoto" region that only repeats the h1.

### X7. Focus visibility in light and dark. **note**, pass, except C5/C6
- Evidence: every HTML link computes `outline: 2px solid var(--color-text)` with 3px offset. That is 14:1 against the background in both schemes. The skip link appears on focus and is first in tab order.

### X8. Small target on the "Every article and essay, in one list" link. **note**
- Evidence: 16–17 px tall in all three directions (Tab walk rects). It passes 2.5.8 through the spacing exception, since no neighbour sits within 24 px. Unlike its siblings it has no `padding-block`.
- Fix: add `padding-block: var(--space-3xs)` for consistency.

### X9. prefers-reduced-motion. **note**, pass
- There are no animations or transitions, and no `scroll-behavior: smooth`. In-page jumps are instant. The global reduced-motion reset in `base.css` is harmless future-proofing.

### X10. Reflow at 200% and 400% zoom. **note**, pass
- At 320 px all three show no horizontal scroll, including with text-spacing overrides. B's `.section-title { min-block-size: 2lh }` grows with the text and does not clip. The only reflow issue is the SVG text in C7.
